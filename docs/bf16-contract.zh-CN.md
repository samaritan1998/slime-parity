## 计算契约的实测结果

模型仍是合成的四层 Qwen3 Dense 和 Qwen3-MoE：hidden 128、4 个 query heads、2 个 KV heads、head dimension 32、vocab 512。MoE 有 4 个专家，每 token 选择 2 个。每次执行三步 AdamW，batch 16、microbatch 1、LR `1e-5`、betas `[0.9,0.999]`、epsilon `1e-8`，weight decay、clipping、dropout 均为零。参数初始化先舍入到 BF16，主参数和累加梯度为 FP32；损失按全局监督 target token 数归一化。

运行时为 PyTorch `2.11.0+cu129`、Transformers `4.57.6`、Transformer Engine `2.10.0`。实测 Attention 选择的是 **FA2**，其安装版本为 `2.7.4.post1`。Profiler 记录了对应 CUDA kernel；八个相关 TE Python 文件与公开 `v2.10` 源码相同。这些证据不能证明编译后二进制与某个源码提交完全一致。

| 环节 | 已核对的行为 | 仍需保留的边界 |
| --- | --- | --- |
| Linear | BF16 前向和输入梯度；权重梯度以 BF16 输入做 FP32 GEMM 并累加 | 分别计算 Q/K/V 或 gate/up 后累加 BF16 输入梯度，会引入额外舍入；独立诊断改为联合投影。 |
| RMSNorm、RoPE、SwiGLU | 显式 FP32 中间计算及 BF16 写回与原生局部结果接近，保留稀疏舍入差异 | 不承诺 FP32 归约顺序、FMA 或编译器生成算术逐位一致。 |
| Embedding | 本次 CUDA 小输入路径按 32 个位置形成部分和，并有 BF16 梯度写回 | 一次 FP64 scatter 后只舍入一次不是相同算法；当前参考限制了适用输入规模。 |
| Attention | 独立实现 FA2 一 tile 的指数、概率、反向 dS 和 GQA 中间写回边界 | 限定 causal、无 dropout、D32、单序列长度 1–128；不是长序列或 CP backend 资格。 |
| Router | 实际使用 PyTorch FP32 fallback；36 项局部前向/反向比较逐元素一致 | 固定 Megatron 的可选 TE GEMM 导入失败，不能把未执行的 TE 路径当作实际算术。 |
| 加权 SwiGLU | 选中专家的 FP32 概率在激活写回 BF16 之前参与计算 | 局部前向及 gate/up 梯度一致；概率梯度仍有 FP32 归约残差。 |

独立 Attention 公式先自行计算期望值，再测量 native。源码中的关键舍入边界见 [FA2 forward](https://github.com/Dao-AILab/flash-attention/blob/v2.7.4.post1/csrc/flash_attn/src/flash_fwd_kernel.h) 和 [backward](https://github.com/Dao-AILab/flash-attention/blob/v2.7.4.post1/csrc/flash_attn/src/flash_bwd_kernel.h)。三组局部输入中，补齐这些边界后，forward 和 dV 全部逐元素一致；dQ、dK 仍有少量残差。一次 GQA 抵消后的 dK 差异不能称为「一个输出 ULP」。

准备发布的诊断源码另做了 GPU 回放：与封存控制相比，Dense 两端各 708 项、MoE 两端各 1,428 项训练观测均逐字节一致。

补充的 65-token mask 用例也完整执行。Dense 有 69/708 项失败；MoE 有 308/1,428 项失败。MoE 该用例第 0 步 logits 最大差为 `0.005859375`，后两步为 `0.064453125`。这说明仅看第一步不足以判断训练轨迹。

文本用例重复运行的两端训练观测全部逐字节一致，包含有符号零。另用各端自己的完整 logits 和实际 token/mask，独立重算了 576 个样本、36 个全局 loss；文本与 mask 用例的监督分母分别为 1,008 和 683。捕获 loss 与 FP64 移位交叉熵的最大差为 `8.032e-7`。输入身份与实际消费记录相符；这项检查支持当前目标函数与归一化语义，不给出新的数值门限。

## 混合并行的梯度缩放

在八卡 TP2/CP2/EP2/SPon/PP2/ETP1 的 MoE mask 用例中，探针采集了实际 `DDP.scale_gradients` 调用前后的 FP32 梯度缓冲区，包括 dense、expert 和 padding 区域。三步、八个 rank 共 48 份缓冲区观测，包含 6,729,216 个元素。探针运行的全部 1,428 项规范张量记录与同配置、未加探针的矩阵运行逐字节相同。

实际缩放系数全部等于 `FP32(1/(683*2))`，其中 683 是本用例的全局监督 target token 数，2 是 CP 度数。用各缓冲区实际输入与实际 FP32 系数独立做 FP64 乘法，再舍入到 FP32，与实际输出逐字节比较，全部元素一致。实际 dense/expert 通信组也与声明拓扑相符。

这项检查确认了上述配置中被采集的缩放操作，没有单独证明此前反向图、梯度通信或所有并行组合正确；也没有据此修改门限。

## 混合并行的梯度归约

同一八卡 MoE mask 配置另做了归约探针。探针运行与未加探针的矩阵运行，全部 1,428 项规范张量记录逐字节相同。三步、八个 rank 的 dense/expert 缓冲区均有完整 bucket 及参数区间记录，覆盖 24 个「bucket × step × 参与组」观测和 48 个 rank 所属输出分片；这里的 24 不是不同 NCCL communicator 的数量。

每次被采集的 reduce-scatter 均为两个参与者、FP32、SUM。用两个实际 FP32 输入独立做 FP64 加法，再舍入到 FP32，与实际所属输出分片比较：3,364,608 个元素全部逐字节一致，参数区和 padding 区均无差异。调用前的缓冲区缩放、从原始同步前输入重放的结果也全部一致，比较保留了有符号零。

实际观测边界是 Megatron 调用的 Slime 通信包装函数及原同步 coalescing 调用返回后的输出。其包装源码与 plan 中冻结的文件一致；包装函数的底层闭包目标和运行时 c10d 函数源码未直接采集。因此不能据此证明 NCCL 内部指令、其他通信组大小、异步模式、AVG 或完整反向图正确。这项诊断没有选择新门限。

## 第一处 Dense 差异

逐层探针覆盖 75 个观测点、16 个样本。探针两端的全部 708 项训练观测与未加探针版本一致。

第 0 步第一层 Attention 之前的采集点及实际 Q/K/V 全部一致。Attention 输出的 131,072 个元素中有 18 个不同，最大绝对差 `0.00048828125`、相对 L2 `2.45401e-5`。同一独立公式在 CPU 上用捕获的 Q/K/V 重算，逐位复现全部 GPU reference 输出。差异随后传播，最终 logits 相对 L2 为 `0.00239559`。

其中 16 个差异集中于三个输出行，邻近的 BF16 指数舍入边界变化可以复现这些 native 行；另一个元素对 PV 累加顺序敏感。还有一个元素未定位到具体内部指令。这些是对舍入敏感性的诊断，没有直接捕获 native 的指数和归约中间值，不能据此宣称已证明全部内核行为。

## TP2 行投影的舍入边界

W2/TP2/CP1/SPoff/PP1 的 Dense 成对运行中，探针前后的 708 项规范张量观测逐字节相同，两个 TP rank 的实际输出也相同。用采集到的 BF16 局部输入和权重，在 CPU 上对相同操作数独立计算 FP64 公式，可以比较第 0 步第一层的两种舍入契约：

| 投影 | 元素数 | 理想部分积相加后统一舍入 BF16，与实际不同的元素 | 各部分积先舍入 BF16，再相加并舍入，与实际不同的元素 |
| --- | ---: | ---: | ---: |
| Attention 输出 | 131,072 | 48,779 | 1 |
| MLP 输出 | 131,072 | 48,943 | 8 |

按局部 BF16 写回公式计算，剩余最大绝对差分别为 `1.90735e-6` 和 `3.05176e-5`；在各部分积的 BF16 转换前再加一次 FP32 舍入，MLP 剩余差异降至 5 个。实际模块记录确认是 BF16 行投影，没有 bias、FP8、Userbuffers 重叠或 symmetric all-reduce。这与公开 [TE GEMM 写回后再做集体通信的代码顺序](https://github.com/NVIDIA/TransformerEngine/blob/v2.10/transformer_engine/pytorch/module/linear.py#L320)相符。

探针没有采集原生 GEMM accumulator 或 all-reduce 前的局部结果，不能据此证明其内部指令顺序、所有通信实现或完整并行模型的误差预算。

## MoE 路由与误差传播

三步 MoE 探针保持两端各 1,428 项训练观测逐字节不变，每端覆盖 12,288 个 layer-token 位置，每步 4,096 个。各端选出的集合均符合自身实际 FP32 gate logits 的 top-2，也符合用其自身输入和有效权重独立重算的 FP64 投影；本次观测中没有 cutoff 精确平局或 FP64 top-2 逆序。

| 步骤 | top-2 集合不同的位置数 | 按层分布 | 最终 logits 最大绝对差 | 可能受影响的输出 token | 这些 token 占 logits 平方误差的比例 |
| --- | ---: | --- | ---: | ---: | ---: |
| 0 | 3 | `[0,0,2,1]` | 0.05859375 | 54/1,024 | 79.75% |
| 1 | 11 | `[2,1,6,2]` | 0.05322265625 | 311/1,024 | 64.20% |
| 2 | 16 | `[3,5,5,3]` | 0.05859375 | 322/1,024 | 73.35% |

普通 BF16 控制首步有 18 处路由集合差异。FA2 控制中，不在上述潜在影响范围内的 token，其三步 logits 最大绝对差分别为 `0.005859375`、`0.0078125`、`0.009521484375`。影响范围按 causal 依赖计算，建立的是位置关联，不能把表中比例当作路由导致的因果误差占比。三步完整 logits 的最大差均超过原 `0.025` 门限；局部 top-2 选择一致不能证明此前的激活或完整训练轨迹正确。参考实现始终独立选路，没有采用 native 的路由结果。

## AdamW 独立重放

新增的 NumPy 重放工具读取每端自己的梯度、前一步主参数和 moments，独立计算 AdamW，并核对 `update = parameter - initial` 及跨步主参数连续性。它不以另一端的 optimizer 输出作为期望值。

三步探针记录到实际优化器链为 `ChainedOptimizer` → `DistributedOptimizer` → `transformer_engine.pytorch.optimizers.FusedAdam`，并保存了已加载扩展与基础库的身份。这确认了本次运行使用的类，不能据此证明编译后二进制完全对应某个上游 tag。

[公开 TE FusedAdam 源码](https://github.com/NVIDIA/TransformerEngine/blob/v2.10/transformer_engine/common/multi_tensor/adam.cu#L541)先把 beta 转成 FP32，再计算 `1-beta`。例如 beta2 的有效值为 `0.9990000128746033`，对应差值为 `0.0009999871253967285`；HF/Python 标量准备的顺序不同。仅改变重放的标量准备顺序，MoE native 二阶矩最大残差从 `9.73110e-12` 降至 `2.77275e-14`，存储后 parameter/update 残差从 `5.96046e-8` 降至 `3.72529e-9`；HF 的 moments 残差反而增大。这支持标量舍入解释，不意味着每个元素或每个 update 都改善。

工具保留 FP64 与显式 FP32 两组公式。它没有模拟所有 CUDA FMA、近似数学函数或最终融合减法，也没有给这些残差自动定门限。返回 `complete_report_only` 表示证据读取和重放完成，不是验收通过。[使用方法](../examples/diagnostics/bf16/README.md#replay-adamw-from-captured-state)说明了固定优化器契约和源码核验范围。

## 首步更新为何放大梯度差异

额外的 CPU 分析覆盖两个单卡（W1）、64-token FA2 文本控制第 0 步的全部参数元素。先固定以 epsilon 为基准的梯度分桶、符号分类和公式，再读取本次数组；此前已分析过同一开发数据，因此这不属于盲测或留出验收。下表只统计原策略中 `abs(update_native - update_reference) > 3e-6` 这一项，不代表完整策略的判定。

| 模型 | 参数元素总数 | 超过 update 绝对门限 | 其中两端非零梯度异号 | 其中仅一端梯度为零 | 其中两端非零梯度同号 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Dense | 722,304 | 946 | 854 | 60 | 32 |
| MoE | 1,117,568 | 4,943 | 4,762 | 60 | 121 |

两类失败元素中，都没有两端梯度绝对值同时小于等于 epsilon（`1e-8`）的情况；只有一端梯度绝对值小于等于 epsilon 的分别为 97 和 195 个。因此不能把这些更新差异统一称为「epsilon 以下的噪声」。在本次零 moments、无 weight decay 的首步契约下，实数公式为 `-lr*g/(abs(g)+eps)`；梯度异号且大小超过 epsilon 时，两端更新差可接近 `2*lr = 2e-5`。

从每端自己的梯度和初始主参数独立重放，再做 FP32 存储舍入，三种公式都复现了上述全部越界事件，且没有额外越界事件。三种公式分别使用两端各自标量的 FP64／FP32 重放，以及统一名义标量的 FP64 对照。预测的两端 update 差与实际差之间，最大残差均为 `3.72529e-9`。这说明本次首步的大更新差可以由已捕获的梯度差经 Adam 映射解释；它没有解释上游梯度为何不同，也不为梯度、后续 moments 或整条训练轨迹提供通过结论。全部元素和原门限保持不变。

## 完整矩阵与门限校准

本轮另建开发对照矩阵，保留原两种模型、两个输入 case 和全部请求组合，使用明确标识的独立参考与[专家 DP 实验补丁](../examples/patches/README.md)。矩阵固定 W8、VPP1，TP/CP/EP/PP/ETP 分别取 1 或 2，SP 分别关闭或开启。原策略不变，新矩阵不覆盖历史报告。

256 个请求行中，64 个不符合通用拓扑约束，64 个不适用于 Dense，剩余 128 个为必检行。每行包含模型、输入 case 和并行配置；单卡定位实验不计入这个分母。

| 模型 | 必检行 | 执行完成 | 数值失败 | 数值通过 | 执行失败、未验证 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Dense | 48 | 48 | 48 | 0 | 0 |
| MoE | 80 | 64 | 64 | 0 | 16 |
| 合计 | 128 | 112 | 112 | 0 | 16 |

Dense 文本用例每行有 66–80 项门限失败，mask 用例有 69–79 项；MoE 分别为 320–476 项和 308–523 项。执行完成表示三步计算和证据检查完成，不表示数值正确。完整逐行计数见结构化结果中的 `development_matrix`。

16 个执行失败行的实际 traceback 均命中后端对 MoE `TP>1 && SPoff` 训练的拒绝检查。分类以封存日志为依据；命中该检查不能证明绕过它之后一定可用。这些行仍计入必检分母并保持未验证，没有被排除或改为通过。

已单独生成并封存 10 份新 fixture：两种模型各有 3 份预留校准数据和 2 份预留留出数据，权重与 token 分别设种子。生成过程没有执行模型、检查路由或筛选样本；实际哈希保存在结构化结果中。目前只覆盖原三步、64/65-token 配方，没有完成这些数据的数值评估。

正式校准仍需：冻结算子契约、误差预算及候选规则；对新数据执行健康对照；在查看留出结果前固定门限；证明同一门限能检出映射、mask、归约、路由和 optimizer 故障。近零梯度可能造成 Adam 更新异号，必须同时检查梯度、moments 和各端独立重放，不能仅扩大 update 上限。未支持的 SP 组合和执行失败继续阻止完整域验收。
