# GPU 实测记录：2026-10-26

[English](gpu-validation.md) | [简体中文](gpu-validation.zh-CN.md)

Slime 原生路径已在 1 卡和 8 卡上，完成小型 Qwen3 稠密模型和 MoE 模型的三步优化器更新。与独立 HF 参考比较后，结果为 **`numerical_failure`**。这证明验证路径取得了实际 GPU 证据，但模型尚未通过冻结的数值门限。

[结构化摘要](gpu-validation-2026-10-26.json) 提供配置行、失败门限数量和逐步 logits 误差。摘要按字段白名单生成，不包含原始张量、日志或运行路径。

运行环境的 cuDNN 版本探测失败：PyTorch 期望 `9.17.1`，安装的 cuDNN 包为 `9.16.0.29`。验证保留了该错误，并使用 Flash attention 执行，不能据此认定 cuDNN attention 已兼容。隔离的 HF 环境关闭了可选 kernel 自动发现，没有加载远程模型代码。

两个模型均为随机生成的测试权重：seed 为 417，词表大小为 512，hidden size 为 128，4 层，4 个 attention head，2 个 KV head，dropout 为 0。稠密 FFN 大小为 256；MoE 有 4 个专家，采用 top-2 路由，专家 FFN 大小为 128，辅助损失和 z-loss 均为 0。独立参数映射分别包含 39 个和 79 个规范张量。

候选使用 BF16，HF eager 参考使用 FP32 计算；两侧初始权重先按 BF16 舍入，初始值相同。每组输入包含 16 个样本，计划更新 3 步；执行完成的配置实际完成全部 3 步。AdamW 学习率为 `1e-5`，betas 为 `[0.9, 0.999]`，epsilon 为 `1e-8`，不使用 weight decay 或梯度裁剪。目标函数按全局有效监督 token 数归一化。两个用例的长度分别为 64 和 65，后者还覆盖 loss-mask 边界。

## 差异定位

固定版本的 `MoELayer.forward` 会拒绝 attention TP 大于 1、SP 关闭的训练配置，与 EP、ETP 大小无关。矩阵规划器的通用约束没有排除全部此类配置；`eligible` 表示通过声明的规划约束，仍需原生预检。这些后端拒绝执行的行保留在必检分母中，状态为 `execution_failure`／`unverified`，不计为数值失败，也不在事后从覆盖统计中移除。

固定后端中的 MoE 配置 TP=1、EP=1、ETP=2，在训练前就未通过优化器主参数的完整覆盖检查。源码显示，`TEGroupedLinear` 按 expert TP 切分专家权重，却在 EP=1 时把它们归入普通 DP 优化器。attention TP 与 expert TP 不同时，该优化器组可能混合不同的专家权重切片。

CPU 最小复现使用固定版本的 checkpoint factory 和优化器范围算法，在 PP=1、PP=2 下都重现了 FC1 gate/up 主参数各缺半的问题，原模型参数的覆盖则完整。仅将合成用例归入 expert DP 后，主参数恢复完整覆盖；TP=ETP=2 的对照原本就完整。这确认了固定源码中的分组不一致，但合成用例不能替代失败 GPU 的实际 buffer 范围转储。GPU 运行保留原后端、训练语义和覆盖检查，这些行仍为执行失败，数值结果保持未验证。

相反方向的 TP=2、EP=1、ETP=1 在开启 SP 后，初始参数覆盖完整，但首次更新前的专家梯度副本一致性检查失败。这与分组问题相符，不过校验和不一致本身既不能给出差异大小，也不足以完整证明运行时根因。该结果仍属于证据失败，不是已经量化的数值门限结果。

稠密模型单卡 text 用例在 step 0 的最大参数更新差异约为 `2e-5`，学习率为 `1e-5`。更新差异超过 `1.8e-5` 的 2,216 个元素，全部对应两侧梯度反号。两侧 Adam 状态与各自梯度一致，`update = parameter - initial` 也逐元素成立。这说明小梯度差异能够放大为更新差异，但不能证明梯度差异合理，失败结果保持不变。

MoE 在首次更新前就有前向差异：单卡相对 HF 的 logits 最大绝对误差为 `0.100845`，坐标为 `[sample=14, token=33, vocab=338]`；混合配置在同一坐标的误差为 `0.098892`。直接比较两种 Slime 配置时，最大 logits 差异仍有 `0.065430`，router 梯度聚合相对 L2 为 `6.343%`，一个专家张量达到 `12.045%`。这种直接比较仅用于定位，不能替代独立参考或成为新的验收结论。

独立的路由探针保留了原有三步训练。六个参考／候选阶段各比较了 476 个首步规范张量，共 2,856 次阶段／张量比较，均与原始运行逐位相同。每侧完整覆盖 4 层、16 个样本：text 有 4,096 个层／样本／token 位置（`4 × 16 × 64`），masked-boundaries 有 4,160 个（`4 × 16 × 65`）；混合配置的后一个用例剔除了 192 个填充观测行。所有配置的每一层都实际选中过全部四个专家。HF 选择按其原始路由公式推导，Slime 选择和权重则取自原生 router 的实际返回值。

| 首步用例 | HF → Slime 各层改选专家的 token 数 |
| --- | --- |
| 单卡 text | 4 / 5 / 3 / 11 |
| 混合 text | 5 / 6 / 5 / 5 |
| 混合 masked-boundaries | 2 / 6 / 7 / 5 |

Slime 单卡与混合 text 之间，各层也有 1 / 1 / 4 / 8 个 token 改选专家。使用相同的初始 router 权重、分别对捕获的输入做 CPU FP32 投影，全部复现了观测到的 top-2 集合，gate logits 最大残差为 `1.788e-7`。差异已经存在于 router 输入中，但尚不能确定具体来自哪个上游运算。

另一个 CPU 前向诊断强制 HF 使用 Slime 的专家集合，再用当前 HF logits 重算选中专家的归一化权重。该诊断使用 PyTorch `2.14.1+cpu`、Transformers `4.57.6`；未干预的 CPU HF 与 GPU HF 最大误差为 `7.153e-7`，复制 forward、强制 HF 自身专家集合、恢复原计算三项对照均逐位一致。

| 首步用例 | 相对 Slime 的 logits 最大差异：干预前 → 后 | 超过 0.025 的 token 数：干预前 → 后 |
| --- | --- | --- |
| 单卡 text | 0.100845 → 0.007553 | 20 → 0 |
| 混合 text | 0.098892 → 0.008276 | 18 → 0 |
| 混合 masked-boundaries | 0.056067 → 0.008142 | 19 → 0 |

表中仅比较 step 0，即首次更新前。混合 masked-boundaries 的三步最大误差为 `0.081124`，出现在 step 1；本干预未覆盖后续步骤。

在这些用例中，改变专家集合能解释大部分观测到的前向差异，剩余相对 L2 约为 0.64%–0.69%。该干预改变了路由，且没有执行反向或优化器更新，不能据此将原运行改判通过，也不能证明梯度、更新正确或确定上游 GPU 故障。

在单卡与混合配置的 text 用例 step 0 聚合比较中，梯度没有呈现 CP／EP 多乘或少乘 2 倍的特征，但该指标不能排除局部映射、路由或数值错误。[原始诊断策略](../examples/policies/tiny-qwen3-diagnostic.json) 未作放宽；该策略不属于经过校准的 BF16 通用验收建议。

## 修复与复现

结构化摘要包含每次运行冻结的库源码哈希。MoE 完整矩阵使用的 26 个库 Python 文件与本次发布一致。稠密矩阵使用较早快照，尚无下述新增计算模式预检和环境记录字段，其采集、比较代码相同。CPU 回归覆盖本次发布源码。

本次发现并修复了 THD 前向采集的坐标问题：Slime 先按 CP 切分样本，再对本地序列做 TP 对齐填充。观察器现在按该顺序还原 token 坐标，并排除填充序列。独立复查在 CPU 上，用固定版本 Slime 的原生 batch builder 对照了 216 个配置下的 810 个 CP rank 局部布局用例，结果一致；这些不计入 GPU 实测配置数。

运行环境记录会保留 cuDNN 探测错误，避免该信息查询中断其他 GPU 路径。比较器还会在单个张量内复用已校验文件的句柄，减少 TP 碎片区间反复打开文件的开销；路径约束、截断检查和句柄释放均保留。

原生预检补充了仅检查参数 dtype 无法发现的计算模式：FP8／FP4 计算或参数存储、Kitchen 量化配置、以低精度保存的反向激活、实际启用的 TE 模块级量化覆盖、INT4 伪量化、强制路由及请求的路由重放。这些模式需要专用参考与适配器。库会记录相关环境开关，并明确拒绝不支持的模式，不会静默修改开关。

CPU 回归测试通过 124 项。公开的 [复现脚本](../examples/README.md#synthetic-qwen3-gpu-fixtures) 已生成与 GPU 实测逐元素相同的权重，输入、参数映射和训练参数也一致。脚本默认不设置门限，复现原始诊断需要显式选择策略文件。其他模型架构、更高并行度、VPP、多机、RL 和多模态目标不在本次结论范围内。
