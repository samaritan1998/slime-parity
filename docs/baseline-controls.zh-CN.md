# 基线与后端对照：2026-10-26

[English](baseline-controls.md) | [简体中文](baseline-controls.zh-CN.md)

本轮补充 HF 精度控制，定位稠密模型的早期差异，并验证专家参数归属补丁。
**目前仍未通过数值验收。** 原完整矩阵结果保持不变。[结构化摘要](baseline-controls-2026-10-26.json)
仅包含按白名单导出的指标和公开源码身份，不含运行路径或日志。本轮在同一节点上
使用 1、4 或 8 张 GPU，沿用 [原始记录](gpu-validation.zh-CN.md) 固定的环境和合成样例。

## 独立参考控制

三组公开 HF 精度控制在同一个单卡稠密 Qwen3 文本样例上完成了三步优化器更新。每步包含 16 个长度为 64 的样本。**按原固定门限判定，三组结果均为 `numerical_failure`。** 结构化摘要记录了逐步指标、未修改的策略哈希，以及提交 `4d4e12422d0f0cdd1fbbeb9cbae9420defb92331` 对应的全部 26 个库源码文件哈希。

`fp32` 使用 FP32 参数和计算、16 个样本的完整 batch，并在反向传播前归一化。`autocast` 将计算精度改为 BF16，参数仍为 FP32。`bf16_micro_after` 使用 BF16 参数和大小为 1 的 microbatch，梯度以 FP32 累加后，再按全局监督 token 数归一化。三组均保留 FP32 优化器主参数和 buffer 的构造精度。BF16 autograd 梯度可能在累加前已经舍入，因此仍不等价于 TE 融合权重梯度算术。

| 控制组 | 失败门限数（梯度 / 更新 / 一阶矩） | logits 最大绝对误差 | 梯度相对 L2 最大值 | 更新最大绝对误差 |
| --- | ---: | ---: | ---: | ---: |
| `fp32` | 71 / 708（5 / 57 / 9） | 0.0130851 | 0.0102591 | 1.99946e-5 |
| `autocast` | 82 / 708（12 / 55 / 15） | 0.0117188 | 0.0107712 | 1.99955e-5 |
| `bf16_micro_after` | 76 / 708（8 / 57 / 11） | 0.0112305 | 0.0103437 | 1.99974e-5 |

表中最大值取自第 0–2 步。梯度相对 L2 按每步全部参数的梯度拼接计算；验收仍逐张量判定。前向输出、loss、初始及更新后的主参数、二阶矩均通过各自门限。

另设的首步探针在每组、每端覆盖 75 个观测点 × 16 个样本 × 64 个 token。六个探针阶段与各自先前未加探针的控制运行相比，全部 708 项训练张量与步数组合均一致。公开 FP32、autocast 实现与这些控制运行也逐字节一致。公开 BF16 参考的 708 项中有 706 项一致，仅第 0、1 步 loss 各差 `4.76837158203125e-7`，即 1 个 FP32 ULP；native 端全部 708 项一致。逐层探针仍归属于原控制实现。旧 helper 记录 loss 时使用 Python 整数作分母，公开实现使用 device FP32 分母，与这处标量舍入差异相符；logits、梯度、主参数、更新和优化器状态均未改变。

FP32、autocast 的首处差异在 `layer0.input_norm`，该处 HF 输出为 FP32，native 输出为 BF16。使用 BF16 参数后，embedding、输入归一化、Q/K/V 投影及 Q/K 归一化均一致，首处差异转到 RoPE：`layer0.q_rope`、`layer0.k_rope` 的最大绝对差均为 `0.015625`。独立 CPU 公式保留 BF16 系数和中间舍入，使用捕获的输入重现了四层全部 **786,432 个 HF Q/K RoPE 输出元素**。保留 FP32 中间算术的结果接近 native，但仍有残差。这支持舍入差异的诊断，尚不能证明 GPU 内核或反向传播正确，也不改变原失败结果。

单独的 GPU RoPE 算术诊断也完成了三步，但仍有 **80/708 项门限失败**，普通
`bf16_micro_after` 为 76/708。三步 logits 最大绝对差均为 `0.009765625`。
三步梯度相对 L2 从 `0.0103437 / 0.0102481 / 0.0101069` 变为
`0.0101181 / 0.0100270 / 0.0100895`；更新相对 L2 从
`0.121889 / 0.0336795 / 0.0199673` 变为 `0.120477 / 0.0323532 / 0.0189817`。
部分聚合误差下降，但失败的逐张量门限更多，因此不能将这项改动当作验收修复。
native 端全部 708 项观测逐字节不变。参考记录了 48 次系数计算、192 次旋转，
并确认恢复了原函数。

公开的 [RoPE 诊断示例](../examples/diagnostics/README.md) 保留实测执行结构，
发布时仅修改模块说明和一条错误文案。它是显式选择的参考算术实验。6 项 CPU
检查在 Transformers 4.57.6 下通过；其他 HF 版本会明确跳过 4 项集成检查，
两项纯 PyTorch 旋转检查仍可运行。提交 `4d4e124` 的 HF 控制实现通过了
150 项 CPU 回归，其中包含 36 项 HF 测试。加入诊断示例后，完整 CPU 测试在
Transformers 4.57.6 下通过 156 项；在 Transformers 5.13.0 下，RoPE 算子测试
通过 2 项，4 项限定版本的集成测试明确跳过。

## 专家参数归属修复

四组原版与补丁版对照使用相同的小型 MoE 文本样例：16 个长度为 64 的样本、
计划执行三步 AdamW、原固定门限，以及 `a57421d` 的库源码。CP、EP、VPP 均为 1。
运行时版本、权重和优化器契约与 [原始 GPU 记录](gpu-validation.zh-CN.md) 相同。
本轮没有用补丁重跑完整矩阵；原矩阵的 128 个必检配置及失败记录保持不变。

| GPU 数 | TP | ETP | SP | PP | 原版 | 补丁版 |
| ---: | ---: | ---: | --- | ---: | --- | --- |
| 4 | 1 | 2 | 关 | 1 | 初始主参数缺少 393,216 个元素 | 执行完整；468/1,428 项门限失败 |
| 4 | 2 | 1 | 开 | 1 | 786,432 个专家梯度元素存在副本冲突 | 执行完整；507/1,428 项门限失败 |
| 4 | 2 | 2 | 开 | 1 | 执行完整；531/1,428 项门限失败 | 全部 1,428 项观测逐字节不变；失败结果相同 |
| 8 | 1 | 2 | 关 | 2 | 初始主参数缺少 393,216 个元素 | 执行完整；468/1,428 项门限失败 |

探针在原有检查之前读取真实 DDP buffer、优化器组及主参数、梯度的持有区间。
TP1/ETP2 原版把不同权重切片放入同一个 dense DP 组，补丁改为 expert DP 组。
TP2/ETP1 原版的初始覆盖完整，但 786,432 个专家梯度元素全部存在规范副本冲突；
改用 expert DP 后，本次对照中的冲突消失。

每组补丁版均有完整封存的 1,428 项张量与步数组合，237 项
`update = parameter - initial` 检查和 158 项跨步主参数连续性检查通过。
128 条 rank 局部专家参数记录全部使用预期的 buffer 组。这些是归属和执行检查，
**不代表数值验收通过**。失败原版只提供核对过哈希的诊断探针，没有完整 stage
封存记录。探针也不能独立证明每次集体通信及其缩放都正确。

[实验补丁及应用说明](../examples/patches/README.md) 固定了后端源码版本。
补丁只修改 `TEGroupedLinear` 的一处分类，库不会自动应用；原有通信标志和后端
SP 要求均保留。另有 18 项 CPU 分类检查和 20 项模拟归属检查，与真实 GPU
证据分开记录。支持原来被 SP guard 拒绝的组合，还需要单独处理 token 归属和
梯度归一化，不能仅删除检查。

## 距离验收仍需完成的工作

1. 明确 BF16 算术契约，独立核对前向与反向算子。定位 RoPE 后，稠密基线仍未
   通过；HF BF16 梯度存储也与 TE fused wgrad 存在差别。
2. 用已核验的控制组、未参与校准的随机种子与输入、故障注入测试建立门限。
   验收前冻结新策略，保留原诊断策略和失败结果。
3. 使用确认后的参考与后端，重跑完整 TP/CP/EP/SP/PP/ETP 矩阵，包含 mask
   边界及混合配置。暂不支持的配置继续显示为未验证。
